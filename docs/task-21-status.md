`Evidence<T>` distinguishes known, absent and unavailable. Completion adds unknown historical time and never-completed states. Known empty arrays/count zero come only from successful relevant queries. Each independent section checks `.error`, rejected promises and missing count values; it retains other available evidence. Missing required singleton/RPC results are unavailable. Diagnostics are fixed safe text; retained run errors use the existing redactor. Client views do not receive cursors, owners, request-cache bodies, credentials or raw database errors. Manual action results strip `syncRunId`, which is also the lease owner's UUID.

## Freshness policy

`MATTER_SYNC_STALE_HOURS` is an optional server variable: a finite positive number of elapsed hours, default **36**. Invalid, zero, negative and infinite values fall back to 36. The comparison is **`now - completed_at >= hours × 3,600,000`**: exactly 36 hours warns; one millisecond before does not. No calendar-day arithmetic participates. Each page/action captures one `now` for status calculations, and Overview shares its page instant with analytics. Display uses validated `APP_TIMEZONE`, default `Europe/Athens`, with an explicit IANA label, independent of browser/host timezone.

A recent attempt, recently dated imported session, metadata completion, failure, skip, cooldown or invocation-budget stop cannot refresh sessions completion. A successfully committed empty terminal page does. A later partial cycle retains the last proven completion. No notifications, new schedule or background polling are added. The existing sync-button countdown remains local UI only.

## Additive database change and compatibility

`20261015141435_truthful_sync_status.sql` was generated using the supported **Supabase CLI 2.48.3** `migration new truthful_sync_status` command. It adds two bounded server-only RLS tables and four exact-signature invoker functions with empty search paths. Existing migrations are unchanged. No existing ingestion, acknowledgement, quota, fencing or repair function is replaced. `record_matter_cycle_completion` runs after the validated receipt write, within the same transaction and existing lease/stream locks. Failed pages roll back evidence; receipt replay returns before the trigger; unchanged/older cycle generations cannot restamp completion. Direct privileged table edits remain the existing trusted administrative boundary, not an ingestion API.

The invocation audit is intentionally independent of ingestion ownership to record lock refusal. It does not grant any ingestion ability or alter leases, retries, quotas or continuation. The generation-status RPC is read only, pins active pointer and all version labels in one SQL snapshot, and initiates no repair, cutover or rollback. Task 20's existing request-pinned readers are unchanged. Other independent status reads are live observations, not a global MVCC snapshot; concurrent ingestion can temporarily make sections reflect adjacent committed states. No mixed generation labels are assembled across requests.

For a future authorized rollout: drain incompatible old application instances; apply the entire migration chain with this additive migration last; deploy compatible code; verify read permissions and ordinary synthetic ingestion. **This task performs none of those production actions.** Before migration, missing new tables/RPCs display unavailable; they never fall back to a green run-success status. Upgraded historical completions remain unknown until a future proven cycle completes. `MATTER_SYNC_STALE_HOURS` needs no environment change unless overriding the default. No dependencies, services, cron cadence or metric definitions change.

Application rollback can leave the additive objects installed. Do not drop status evidence or disable generation/fencing controls. Old UI would restore misleading wording; keep it out of service if truthful status is required. No historical recomputation, generation cutover or rollback is needed for this status feature.
